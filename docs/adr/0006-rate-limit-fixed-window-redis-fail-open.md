# Rate limit — фиксированное окно в Redis на API-ключ; при недоступном Redis запрос проходит

Без лимита один клиент с зациклившимся ретраем может забрать все соединения с БД и остановить
приём платежей для остальных. Счётчик должен быть общим для всех реплик API, поэтому живёт вне
процесса — в Redis. Redis мог бы служить и кэшем идемпотентности, но идемпотентность уже держит
`UNIQUE` в Postgres (ADR 0002): кэш перед ним был бы второй копией истины, которая может
разойтись с первой, и ускорил бы только повторы, а повторов мало.

Решение: на запросы `/api/v1/payments` действует лимит `RATE_LIMIT_REQUESTS` за
`RATE_LIMIT_WINDOW` секунд на API-ключ. Счётчик — ключ `ratelimit:<sha256(api_key)[:16]>:<окно>`,
`INCR` и `EXPIRE NX` в одной транзакции `MULTI`. Сверх лимита — `429` с `Retry-After` до конца
окна; успешный ответ в пределах лимита несёт `X-RateLimit-Limit` и `X-RateLimit-Remaining`
(ответы-ошибки 4xx их не несут: FastAPI собирает их заново из исключения). Ошибка Redis
(недоступен, таймаут `REDIS_TIMEOUT`, нет свободного соединения в пуле) — запрос пропускается без
лимита, пишется предупреждение и растёт `rate_limit_backend_errors_total`.

Альтернативы. Скользящее окно или token bucket на Lua точнее на границе окон, но сложнее, а
защите от перегрузки хватает фиксированного окна. Fail closed (503 при недоступном Redis) делает
Redis точкой отказа приёма платежей; лимит защищает от перегрузки, а не деньги, поэтому его отказ
не должен останавливать бизнес.

## Consequences

- На стыке двух окон клиент может успеть до `2 × RATE_LIMIT_REQUESTS` запросов за секунду.
- Пока Redis лежит, лимита нет; это видно на дашборде («Rate limit»), алерт — на рост
  `rate_limit_backend_errors_total`.
- Ключ один на сервис, поэтому сейчас лимит фактически общий. С ключами по клиентам (см.
  «Сознательные упрощения» в README) он станет лимитом на клиента без изменений в коде.
- Пул соединений блокирующий (`BlockingConnectionPool`): обычный пул сверх `max_connections`
  сразу бросает ошибку, и под нагрузкой лимит молча отключался бы.
- Окно считается по часам реплики API; расхождение часов между репликами сдвигает границу окна
  на величину расхождения.
